# خط لوله یادگیری ماشین — پیش‌بینی رفتار کاربر (چراغ و فن)

این پوشه پایپ‌لاین کامل «داده فرضی → آموزش → استقرار روی ESP32» را در بر دارد.
طراحی کامل در [`Documents/ml-design.md`](../Documents/ml-design.md) توضیح داده شده است.

## معماری در یک نگاه

```
ml/generate_data.py ──► ml/data/synthetic_log.csv ──► ml/train.py ──► main/ml_model_weights.h
      (داده فرضی ۳۰ روز)        (۸۶۴۰ نمونه)         (رگرسیون لجستیک)      (وزن‌های اولیه)
                                                                            │
     ┌──────────────────────────────────────────────────────────────────────┘
     ▼
  ESP32-S3 (main/)
  ├── ml_model.c/h        ریاضیات مدل + خواندن/نوشتن وزن‌ها در NVS
  ├── ml_agent.c/h        تسک تصمیم‌گیر دوره‌ای + یادگیری آنلاین از اقدام کاربر
  ├── virtual_devices.c/h سنسور مجازی حضور و نور (ورودی‌های مدل) + انتشار در MQTT
  ├── time_sync.c/h       SNTP - ساعت واقعی برای ویژگی‌های زمانی
  └── app_state.c         نقطه‌ی متمرکز آموزش: هر تغییر دستی چراغ/فن = یک نمونه
```

## اجرا

```bash
python ml/generate_data.py   # تولید داده فرضی (تکرارپذیر با seed=42)
python ml/train.py           # آموزش + بازنویسی main/ml_model_weights.h
idf.py build flash monitor   # فلاش روی برد
```

## اعداد فعلی (مدل v2 — فقط-بافت، ۱۲ ویژگی)

| مدل | دقت اعتبارسنجی (روزهای آخر) | یادگیری آنلاین |
|---|---|---|
| چراغ | ۹۴.۲٪ | SGD، lr=0.08، هر اقدام کاربر |
| فن | ۹۳.۶٪ | همان |

سقف بایز ≈ ۹۵٪ است (برچسب‌های داده عمداً ۴-۵٪ «خطای انسانی» دارند).
اقدام در حالت خودکار با آستانه‌های اطمینان p≥0.75 / p≤0.25 انجام می‌شود —
سناریوهای کانونی (شب→روشن، روز→خاموش) با وزن‌های استقرار یافته تست شده‌اند.

## قراردادهای حساس ⚠️

این‌ها باید همیشه بین Python و C *دقیقاً* یکی بمانند:

1. **ترتیب و نرمال‌سازی ویژگی‌ها** — `load_dataset_split_features()` در `train.py`
   و `build_features_base()` در `ml_agent.c`
2. **ثابت‌های محیط شبیه‌سازی** — `SUNRISE_H/SUNSET_H` و الگوی برنامه‌ی روزانه بین
   `generate_data.py` و `virtual_devices.c`
3. **`ML_N_FEATURES` و `ML_MODEL_VERSION`** — تغییر هر کدام باید با بازآموزش و
   بازفلاش همراه شود (وزن‌های NVS با نسخه‌ی ناسازگار خودکار نادیده گرفته می‌شوند)

## چرخه‌ی یادگیری روی برد

1. مدل با وزن‌های پیش‌آموزش شروع می‌کند و در حالت **سایه** است: فقط پیش‌بینی
   می‌کند، منتشر می‌کند و با اقدام واقعی کاربر مقایسه می‌شود — بدون هیچ عملی.
2. هر تغییر دستی کاربر (دکمه/LCD/HA/HTTP) یک گام SGD است؛ پنجره‌ی متحرک ۲۰
   تصمیمِ آخر دقت فعلی را می‌سازد.
3. بعد از ≥۱۵ تصمیم با دقت ≥۸۵٪، آن دستگاه خودکار به **حالت خودکار** می‌رود.
4. در حالت خودکار مدل فقط با اطمینان بالا (p≥0.75 روشن / p≤0.25 خاموش) عمل
   می‌کند؛ اقدام دستی کاربر همیشه فوراً اجرا و به‌عنوان نمونه‌ی آموزشی ثبت می‌شود.
5. وزن‌ها هر دوره (۳۰ ثانیه در صورت تغییر) در NVS ذخیره و بعد از ریست بازیابی
   می‌شوند — یادگیری ماندگار است.
6. سوییچ **ML Autonomy** در HA: خاموش = بازگشت به سایه + قفلِ سایه (بدون ارتقای
   خودکار)؛ روشن = هر دو دستگاه خودکار. قفل درِ هیچ‌کدام از این‌ها نیست.

## صرفه‌جویی NVS

یک رکورد ~۹۰ بایتی در namespace `mlbrain` (نسخه + ۲×۹ وزن float + شمارنده‌ها +
cfg). NVS فرسایشی است؛ به همین دلیل ذخیره هر ۳۰ ثانیه و فقط هنگام تغییر انجام
می‌شود، نه بعد از هر گام SGD.
