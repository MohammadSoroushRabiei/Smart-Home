۸. نکات فنی TLS/HTTPS 🔐
`config.servercert`/`config.servercert_len` نه `cacert_pem`
`EMBED_TXTFILES` symbol naming بر اساس مسیر نسبی فایل
`CONFIG_MBEDTLS_EXTERNAL_MEM_ALLOC=y` برای کمبود DRAM حین handshake
`max_uri_handlers` پیش‌فرض ۸ - با هر هندلر جدید هماهنگ نگه دار

۹. نکات فنی Home Assistant / Docker / MQTT 🏠
Docker Desktop روی ویندوز پورت‌ها را روی IP واقعی هم expose می‌کند
`ha-config/`, `mosquitto/data/`, `mosquitto/log/` در `.gitignore`
Mosquitto بدون `mosquitto.conf` هیچ پورتی listen نمی‌کند
MQTT integration در HA به broker با اسم سرویس Docker وصل می‌شود، نه IP
`esp-mqtt` کامپوننت built-in است؛ فقط نیاز به `PRIV_REQUIRES "mqtt"`
معماری قفل دو-لایه: `lock.c` گنگ (فقط رله + fail-safe مستقل)؛ `app_state.c` تنها نقطه‌ی ورودی رسمی
`binary_sensor` به‌جای `lock` کامل برای وضعیت قفل (تصمیم امنیتی تا امن شدن Mosquitto)
`event` entity به‌جای `binary_sensor` برای رویدادهای دسترسی

۱۰. نکات فنی باس I2C مشترک 🔌
مشکل: race condition بین `sensor_task` و `touch_poll_task` روی باس مشترک، بدون timeout داخلی در درایور GT911
راه‌حل فعلی: mutex اپلیکیشنی (`i2c_bus_lock`/`i2c_bus_unlock`) دور هر تراکنش منطقی
قاعده: هر تابعی که lock می‌کند، باید در همه‌ی مسیرهای خروج unlock کند
⚠️ هنوز گزارش قفل‌شدن تاچ رخ می‌دهد - نیاز به بررسی هم سخت‌افزاری (نویز/سیم‌کشی باس) هم نرم‌افزاری (بخش ۳)

۱۱. نکات فنی enrollment و مدیریت چهره 🔐
`HumanFaceRecognizer::enroll()` هیچ ID برنمی‌گرداند (فقط `esp_err_t`) — برای گرفتن ID واقعی، بلافاصله بعد از enroll باید همان تصویر یک‌بار `recognize()` شود
کتابخانه هیچ متد public ای برای لیست کردن چهره‌های ثبت‌شده ندارد — نیاز به لایه‌ی متادیتای مستقل (`face_db.c/.h` روی NVS)
اسم‌گذاری چهره باید از دستگاهی با کیبورد کامل بیاید (گوشی کاربر در `/enroll`)، نه از کیبورد عددی LCD
اعتبارسنجی توکن باید هم روی GET هم روی POST انجام شود

۱۲. نکات فنی مدیریت اتصال MQTT 🔌 — ✅ پیاده‌سازی شد (۲۶ شهریور)

**معماری نهایی (متفاوت از طرح اولیه‌ی این بند):**

- ذخیره‌سازی آدرس بروکر (`mqtt_config.c/.h`، الگوی مشابه `wifi_config`) در NVS به‌صورت رشته‌ی آزاد (IP یا hostname) - از قصد به‌گونه‌ای طراحی شده که در آینده یک آدرس DDNS هم بدون تغییر کد قابل استفاده باشد (برای سناریوی دسترسی بیرونی، بند ۳)
- **تست قبل از ذخیره:** `mqtt_manager_connect_and_save()` یک تابع بلاک‌کننده (حداکثر ~۵ ثانیه، از یک تسک جدا صدا زده می‌شود نه از تسک LVGL) که ابتدا با یک کلاینت MQTT موقت به IP جدید وصل می‌شود؛ فقط در صورت موفقیت، IP در NVS ذخیره و کلاینت اصلی جایگزین می‌شود. اگر همان الان به همان IP متصل باشیم، بدون قطع/وصل دوباره فوراً موفق تلقی می‌شود.
- صفحه‌ی تنظیمات MQTT (`mqtt_setup_screen.c/.h`): overlay با کیبورد عددی (`LV_KEYBOARD_MODE_NUMBER`، چون فقط IPv4 لازم است) + دکمه‌ی Save؛ روی موفقیت بعد از ۱ ثانیه خودکار بسته می‌شود، روی شکست باز می‌ماند و پیام قرمز نشان می‌دهد
- **state machine چهارحالته:** `UNCONFIGURED` / `DISABLED` / `CONNECTING` / `CONNECTED` (خاکستری/خاکستری/نارنجی/آبی) - حالت `FAILED` جداگانه حذف شد؛ بعد از اتمام retry ها مستقیم می‌رود روی `DISABLED`
- **retry دستی:** چون `network.disable_auto_reconnect = true` است، esp-mqtt دیگر خودش reconnect نمی‌کند؛ یک شمارنده‌ی داخلی (`MQTT_MAX_RETRIES = 5`, فاصله‌ی `MQTT_RETRY_DELAY_MS = 5000` با `esp_timer`) این کار را انجام می‌دهد
- **دکمه‌ی HA در صفحه‌ی اصلی به‌صورت toggle واقعی:** تپ وقتی روشن است (CONNECTING/CONNECTED) → خاموش می‌کند (ابتدا پیام `offline` را به‌صورت بلاک‌کننده publish می‌کند، چون قطع تمیز باعث ارسال خودکار LWT توسط بروکر نمی‌شود، سپس `stop`)؛ تپ وقتی خاموش است → روشن می‌کند؛ هولد همیشه صفحه‌ی تنظیمات را باز می‌کند
- **لینک با وضعیت WiFi:** `mqtt_manager_notify_network_available/lost()` از `on_wifi_state_change` در `main.c` صدا زده می‌شود - با وصل‌شدن WiFi، اگر کاربر دستی MQTT را خاموش نکرده باشد (`s_user_disabled`)، خودکار به آخرین بروکر ذخیره‌شده وصل می‌شود (دقیقاً مشابه رفتار خود `wifi_manager` با لیست MRU)؛ با قطع WiFi، MQTT هم قطع و آفلاین می‌شود
- `mqtt_manager_publish_access_event`: از `qos=0, store=false` به `qos=1, store=true` تغییر کرد چون پیام‌های رویداد دسترسی در قطعی‌های لحظه‌ای گم می‌شدند
- تصمیم آگاهانه: از «حدس‌زدن IP بروکر بر اساس شباهت به IP دستگاه» صرف‌نظر شد (بدون رابطه‌ی ریاضی قابل‌اتکا بین IP دو دستگاه مستقل روی یک subnet)؛ به‌جایش مکانیزم فعلی (ذخیره‌ی دقیق + پشتیبانی از hostname/DDNS) هم برای شبکه‌ی محلی فعلی و هم برای دسترسی بیرونی آینده کافی است
