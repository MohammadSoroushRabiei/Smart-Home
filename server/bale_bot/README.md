# ربات کنترل بله (Bale Control Bot)

کنترل چراغ، فن و درب از داخل پیام‌رسان بله. این سرویس **مستقل از سرور attendance** است:

- اعلان‌های ورود/خروج و رویداد درب همچنان از `server/attendance` می‌آیند (همان بات، همان چت).
- این سرویس فقط «کنترل» است و **از MQTT استفاده نمی‌کند** — همه‌ی فرمان‌ها مستقیم روی HTTPS خود برد می‌روند، پس حتی با بروکر قطع هم کار می‌کنند.

```
بله (چت شما) ──polling──▶ سرور بله (tapi.bale.ai) ◀──long poll── bot.py
                                                             │ HTTPS (self-signed)
                                                             ▼
                                              برد ESP32:  /api/light/set
                                                          /api/fan/set
                                                          /api/lock/unlock
                                                          /api/status
```

## دستورها

| دستور | کار |
|---|---|
| `/start` ، `/help` | راهنما + منوی دکمه‌ای |
| `/status` | وضعیت کامل برد (چراغ/فن/درب/سنسورها/ML) |
| `/open` | باز کردن درب — دو مرحله: تأیید با دکمه، بعد رمز |
| `/light on\|off` | چراغ |
| `/fan on\|off` | فن |
| `/cancel` | لغو جریان درب |

درب: بعد از تأیید دکمه‌ای، ربات رمز می‌پرسد؛ پیام رمز مستقیم به `/api/lock/unlock` برد می‌رود و **در هیچ فایلی ذخیره نمی‌شود**. برد بعد از باز شدن ۵ ثانیه خودکار قفل می‌کند و رویداد attendance هم مثل همیشه به شیت/اعلان می‌رود.

## راه‌اندازی

۱. فایل `.env` را از `.env.example` بسازید:

- `BALE_TOKEN` — توکن همان رباتی که attendance استفاده می‌کند (در `server/attendance/.env`).
- `BALE_ALLOWED_CHATS` — chat_id های مجاز با کاما. اگر خالی بگذارید، ربات در «حالت یادگیری» فقط chat_id هر چت را در لاگ (و در پیام پاسخ) نشان می‌دهد و هیچ کنترلی انجام نمی‌شود.
- `BOARD_URL` — آدرس HTTPS برد (مثل `https://192.168.1.42`؛ IP را از صفحه‌ی `/api/status` یا تنظیمات برد ببینید).

۲. اجرا — محلی:

```bash
python -m venv .venv && .venv/Scripts/activate   # ویندوز
pip install -r requirements.txt
python bot.py
```

یا با داکر:

```bash
docker compose up -d --build
```

۳. بعد از استارت، ربات به چت‌های مجاز پیام «آنلاین شد» با منو می‌فرستد.

## نکات امنیتی

- فقط چت‌های `BALE_ALLOWED_CHATS` حق کنترل دارند؛ بقیه فقط chat_id خودشان را می‌بینند.
- رمز درب در تاریخچه‌ی چت می‌ماند — بعد از استفاده می‌توانید پیام را پاک کنید (ربات هم یادآوری می‌کند).
- گواهی برد self-signed است و ربات `verify` را خاموش می‌کند؛ ترافیک روی LAN می‌ماند.
- بروکر MQTT هنوز بدون احراز هویت است، ولی این سرویس اصلاً به آن وصل نمی‌شود (همین دلیل اصلی جداسازی از مسیر MQTT بود).

## عیب‌یابی

- «برد در دسترس نیست» → IP برد عوض شده (هات‌اسپات!)؛ `BOARD_URL` را به‌روز کنید.
- هیچ پیامی نمی‌آید → توکن را با `server/attendance/.env` مقایسه کنید؛ اگر attendance همان لحظه اعلان می‌فرستد و ربات نه، احتمالاً شبکه/پروکسی خروجی مشکل دارد.
- دکمه‌ها جواب نمی‌دهند ولی متن کار می‌کند → callback_query در نسخه‌ی بله‌ی شما متفاوت است؛ از دستورهای متنی (`/light on` و…) استفاده کنید.
