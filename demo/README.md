# دموی ارائه — همان فریمور، سخت‌افزار مجازی

مثل `lv_demo_music` ولی مال خود پروژه: **منطق واقعی فریمور** (`app_state`،
`ml_agent` + مدل واقعی، `virtual_devices`، `led/lock` روی GPIO مجازی و تمام
UI) روی پنجره‌ی PC اجرا می‌شود و فقط سخت‌افزار شبیه‌سازی شده است. بدون برد،
بدون WiFi واقعی، بدون سرور — برای ارائه‌ی مجازی و فیلم گرفتن.

## ساخت و اجرا (WSL)

```bash
cmake -S /mnt/d/Project/Smart-Home/demo -B ~/lcddemo-build -DCMAKE_BUILD_TYPE=Release
cmake --build ~/lcddemo-build -j$(nproc)

~/lcddemo-build/smartdemo            # حالت تعاملی
~/lcddemo-build/smartdemo --demo     # سناریوی خودکار از لحظه‌ی شروع
~/lcddemo-build/smartdemo --zoom 2   # پنجره‌ی بزرگ‌تر
```

کلیدها: **F** تمام‌صفحه، **D** شروع سناریو در وسط اجرا. خروج با بستن پنجره.

## چیزی که در دمو می‌بینید

| بخش | وضعیت |
|---|---|
| `app_state` (تک‌منبع حقیقت)، `ml_agent` + مدل واقعی، `virtual_devices`، `led/lock` | **کد واقعی برد** |
| تمام صفحات UI (داشبورد، کیپد، تنظیمات، QRها) | **کد واقعی برد** |
| WiFi | مجازی: اتصال خودکار به DemoNet، اسکن ۳ شبکه‌ی ساختگی در صفحه‌ی setup، اتصال موفق |
| MQTT | مجازی: بروکر لاگ‌شونده — هر publish در ترمینال با topic دیده می‌شود |
| سنسور BME280 | مجازی: دما/رطوبت/فشار متغیر نرم هر ۵ ثانیه |
| چهره | مجازی: دیتابیس با Soroush/Sara، ثبت و حذف کار می‌کند |
| NVS | در حافظه — وزن‌های ML بین اجراها می‌مانند |

## سناریوی خودکار (~۸۵ ثانیه)

WiFi وصل → MQTT وصل → فرمان چراغ از HA → باز شدن درب با «چهره‌ی شناخته‌شده»
(Access Granted + ری‌لاک ۵ ثانیه‌ای واقعی) → فن از HA → سوییچ ML Autonomy
در HA → حالت AUTO: عامل ML واقعی با ورودی‌های مجازی خودش چراغ/فن را
مدیریت می‌کند → صفحه‌ی حضور و غیاب → پایان.

حالت تعاملی همیشه روی آن سوار است: هر کلیک از همان مسیر واقعی می‌رود و
بک‌اند مجازی جواب می‌دهد.

## رمزهای دمو

- رمز قفل: **1234**
- رمز تنظیمات: **0000**

## فیلم گرفتن

پنجره را تمام‌صفحه (F) و با OBS Studio یا `Win+Alt+R` ضبط کنید؛ سناریوی
خودکار دقیقاً همان قصه‌ی ارائه است و چون deterministic است، هر بار یکسان در
می‌آید.

## محدودیت‌ها

- صفحه‌ی setup وای‌فای شبکه‌های ساختگی را نشان می‌دهد (اسکن واقعی مال برد است).
- «تشخیص چهره» رویداد اسکریپتی است؛ دوربین و مدل روی PC شبیه‌سازی نمی‌شوند.
- برق/رله واقعی در کار نیست — همه‌چیز لاگ می‌شود (`[demo] LED/DOOR RELAY`).
